一、概览与快速开始

1.1 Pi 是什么

Pi 是一个极简的终端编码 Agent 框架。它在终端里驱动大模型：读文件、改文件、跑命令；同时把「工作流差异」放到扩展层，而不是堆进核心。

你可以用它：

  • 在仓库里交互式对话改代码
  • 用 AGENTS.md / CLAUDE.md 写项目约定
  • 用 /tree 在会话树上回跳、分支
  • 用扩展做权限门、自定义工具、自定义 UI
  • 用 Skills / Prompt 模板沉淀可复用工作流
  • 用 -p / JSON / RPC / SDK 接入自动化

二、使用 Pi

2.1 交互界面

四个主要区域：

  1. 启动头：快捷键、已加载上下文文件、模板、Skills、扩展
  2. 消息区：用户消息、助手回复、工具调用/结果、通知、错误、扩展 UI
  3. 编辑器：输入；边框颜色表示 thinking 级别
  4. 页脚：工作目录、会话名、Token/缓存、费用、上下文占用、当前模型

编辑器可被 /settings 或扩展自定义 UI 临时替换。

2.6 项目信任（Usage 节摘要）

交互启动时，若项目含需信任的本地资源且无已保存决定，Pi 会询问。信任后才加载 .pi/settings.json、.pi 资源、缺包安装与项目扩展。

信任前仅加载：上下文文件、用户/全局扩展、CLI -e 扩展（它们可处理 project_trust 事件）。

非交互（-p / --mode json / --mode rpc）不弹窗。无已保存决定时，用全局 defaultProjectTrust：ask（默认）与 never 忽略项目受保护资源，always 信任。可用 --approve / --no-approve 单次覆盖。

/trust 写入 ~/.pi/agent/trust.json，当前会话不重载，需重启生效。

三、提供商与认证

Pi 支持 OAuth 订阅与 API Key。内置目录随包装载；配置过的提供商可刷新目录并缓存到 ~/.pi/agent/models-store.json 供离线使用。

  • ChatGPT Plus/Pro（Codex）
  • Claude Pro/Max（第三方 harness 走 extra usage，按 token 计费，不抵扣套餐额度）
  • GitHub Copilot（github.com 或 Enterprise 域名；模型需在 VS Code Copilot 中启用）

3.3 auth.json

权限 0600。auth.json 优先于环境变量。

key 支持：

  • 字面量：sk-...
  • 环境插值："$MY_KEY" / "${PREFIX}_${SUFFIX}"
  • 命令："!op read 'op://...'"（进程生命周期内缓存 stdout）
  • 转义："$$" → $，"$!" → !

还可在凭据里挂 env，用于 Cloudflare Account ID、Azure、Vertex、Bedrock、PI_CACHE_RETENTION、代理等，且优先于进程环境。

3.4 云厂商要点

Azure OpenAI：AZURE_OPENAI_API_KEY + AZURE_OPENAI_BASE_URL 或 AZURE_OPENAI_RESOURCE_NAME；可选 API version 与部署名映射。

Bedrock：AWS Profile / IAM / Bearer Token；支持 ECS 任务角色与 IRSA；Claude 可自动 prompt cache；应用推理配置文件 ARN 可设 AWS_BEDROCK_FORCE_CACHE=1。

Vertex：ADC（gcloud auth application-default login）+ GOOGLE_CLOUD_PROJECT / GOOGLE_CLOUD_LOCATION。

Cloudflare AI Gateway / Workers AI：需 API Key + Account（Gateway 还要 Gateway ID）；多种上游鉴权模式（统一计费、存储 BYOK、内联 BYOK 等）。

3.5 llama.cpp / 自定义

  • llama.cpp：/login llama.cpp，/llama 管理，/model 选择
  • models.json：接 Ollama、LM Studio、vLLM 等兼容 API
  • Extension：自定义协议或 OAuth

3.6 凭据解析顺序

  1. CLI --api-key
  2. auth.json
  3. 环境变量
  4. models.json 自定义提供商密钥

4.4 /tree 分支导航

会话是树：每条有 id / parentId，当前位置是活跃叶子。/tree 可跳到任意历史点继续，不新建文件。

键 动作
↑/↓ 导航
←/→ 翻页
Ctrl/Alt + ←/→ 折叠/展开或在分支段间跳
Shift+L 给选中节点打标签
Shift+T 切换标签时间戳
Enter 选中
Escape 取消
Ctrl+O 循环过滤模式

过滤：default / no-tools / user-only / labeled-only / all；默认可用 treeFilterMode 配置。

选中用户消息：叶子回到其父，消息进编辑器，可改后重发成新分支。选中助手/工具等：叶子移到该点，编辑器空，可继续。选根用户消息：重置为空对话并把原 prompt 放进编辑器。

4.5 /tree vs /fork vs /clone

/tree /fork /clone
输出 同文件 新文件 新文件
视图 整棵树 用户消息选择器 当前活跃分支
用途 就地试替代路径 从早前 prompt 另开 复制当前工作再继续
摘要 可选分支摘要 无 无

4.6 分支摘要

/tree 离开某分支时，可对放弃分支做摘要并挂到新位置。选项：不摘要 / 默认提示摘要 / 自定义焦点说明。branchSummary.skipPrompt 可跳过询问。

4.7 Compaction

当 contextTokens > contextWindow - reserveTokens 时自动压缩；也可 /compact [说明]。

流程概要：

  1. 从新到旧累计，保留约 keepRecentTokens（默认 20000）
  2. 对更早消息生成结构化摘要
  3. 写入 CompactionEntry，下次请求用「摘要 + 保留段」重建上下文

默认设置：

摘要格式大致包含：Goal、Constraints、Progress、Key Decisions、Next Steps、Critical Context，以及 <read-files> / <modified-files>。扩展可通过 session_before_compact / session_before_tree 自定义或取消。

七、定制：扩展 / Skills / 模板 / 主题 / 包

7.1 Extensions

扩展是 TypeScript 模块：可订阅生命周期、注册工具/命令/快捷键/Flag、拦截工具调用、自定义压缩与 UI。

安全：扩展以你的完整系统权限运行。只装可信来源。

放置位置（便于 /reload）：

位置 作用域
~/.pi/agent/extensions/*.ts 或 */index.ts 全局
.pi/extensions/*.ts 或 */index.ts 项目（需信任）

也可用 settings 的 extensions / packages，或临时 pi -e ./path.ts。

可用导入：@earendil-works/pi-coding-agent、typebox、@earendil-works/pi-ai、@earendil-works/pi-tui，以及 node:* 与本地 node_modules。

最小结构：

由 jiti 加载，无需预编译。工厂可为 async（启动前 await）。不要在工厂里开后台进程/socket/watcher；放到 session_start，并在 session_shutdown 里幂等清理。

生命周期（摘要）：

tool_call：可原地改 event.input；返回 { block: true, reason?, terminate? } 可拦截。内置工具可用 isToolCallEventType("bash", event) 做类型收窄。

ctx 常用：ui、mode、hasUI、cwd、sessionManager、model、signal、abort()、compact() 等。命令 handler 另有 newSession / fork / navigateTree / switchSession（勿在普通事件里调，易死锁）。

手把手教程见：从零写一个 Pi Extension。官方详版：Extensions。

7.2 Skills

符合 Agent Skills 标准的按需能力包：目录 + SKILL.md。启动只注入名称与描述；任务匹配时再用 read 加载全文（渐进披露）。也可用 /skill:name。

加载位置：

  • 全局：~/.pi/agent/skills/、~/.agents/skills/
  • 项目（需信任）：.pi/skills/、cwd 与祖先的 .agents/skills/（到 git 根）
  • 包与 settings / --skill

可在 settings 挂 Claude Code / Codex 技能目录：

Frontmatter 必填 name、description。无 description 的技能不会加载。disable-model-invocation: true 时模型侧隐藏，只能 /skill:name 触发。

原文：Skills

7.3 Prompt Templates

~/.pi/agent/prompts/*.md 或 .pi/prompts/*.md。文件名即命令：review.md → /review。

参数：$1 $2、$@/$ARGUMENTS、${1:-default}、${@:N}、${@:N:L}。prompts/ 目录不递归；子目录需在 settings 或包清单中显式声明。

7.4 Themes

JSON 定义 TUI 颜色。内置 dark/light；自定义放 ~/.pi/agent/themes/*.json。/settings 或 "theme": "my-theme" 选择。--use-theme light 或 light/dark 可设本次初始主题。

需定义约 51 个必需 color token（可用 vars 别名）。颜色支持 hex、256 色索引、变量名、""（终端默认）。正在使用的自定义主题文件保存后会热重载。

原文：Themes

八、安全与容器化

8.1 项目信任 ≠ 沙箱

项目信任只控制是否加载项目本地设置/资源/扩展/包，不限制模型之后让工具做什么。

需要信任的资源包括：.pi/settings.json、.pi 下 extensions/skills/prompts/themes、.pi/SYSTEM.md / APPEND_SYSTEM.md、项目 .agents/skills。空的 .pi 目录不算。

AGENTS.md / CLAUDE.md 不受信任开关影响（除非禁用 context files）。

8.2 无内置沙箱

内置工具与扩展以启动用户权限读写文件、跑 shell。这是刻意设计：Pi 要对接本机工具链。半吊子进程内沙箱容易造成「假安全感」。真正隔离应来自 OS / 容器 / 虚拟化。

Prompt injection（来自仓库文件、注释、文档、构建产物）是本地 Agent 的预期风险，Pi 无法可靠杜绝。

8.3 容器化模式

模式 隔离什么 适合
Gondolin 扩展 内置工具与 ! 命令进微 VM 本机跑 Pi，工具进微 VM；鉴权留宿主
Plain Docker 整个 pi 进程 最简单本地容器边界
OpenShell 整个 pi + 策略沙箱 本地/远程托管沙箱，可控网络与推理

扩展跑在 pi 进程所在处：宿主 Pi + 工具路由扩展时，其他自定义扩展工具仍在宿主，除非它们也委托。

十、设计原则与约定

10.1 刻意不做的事

官方写明：Pi 故意不内置 MCP、子代理、权限弹窗、Plan 模式、Todo、后台 bash。需要时用扩展/包安装，或用容器、tmux 等外部手段。

哲学：核心保持小，按你的工作流定制 Pi，而不是反过来。
