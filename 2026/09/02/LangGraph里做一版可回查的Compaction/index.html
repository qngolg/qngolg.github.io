LangGraph 里做一版「可回查的 Compaction」

目标：长 agent 轨迹里，送给模型的是压缩后的工作记忆；完整历史落在可检索档案里。摘要丢了细节时，agent 能自己查回来——接近 Cursor / Claude Code 的做法，而不是 LangChain 早期那种「摘要了就永远没了」。

1. 先分清两层记忆

层 是什么 LangGraph 落点 给模型看吗
Working memory 当前决策需要的高信号 token state.messages + state.summary 每轮都看
Archive 完整 transcript（含工具原文） 独立 store / 文件 / 表，不要指望靠 checkpointer 当唯一真相 默认不看；需要时工具读

Checkpointer（MemorySaver / SqliteSaver / PostgresSaver）负责的是：图状态快照 + 断点续跑。
它适合存「现在工作记忆长什么样」，不适合当「永远可全文检索的聊天库」。

3. State schema

设计要点：

  1. **messages 用 add_messages**：压缩时用 RemoveMessage(id=...) 删旧消息，别手写覆盖整个 list（和 reducer 打架）。
  2. summary 单独字段：压缩后通常变成一条 SystemMessage 或 Human/AI 包装的「此前经过」，不要和用户新消息糊在一起无法区分。
  3. archive_* 与 UI 同源：前端展示历史从 archive 读；模型工作记忆可以短很多。

4. 每轮先归档，再决定是否压缩

经验规则：

  • 先 archive，再 compact。顺序反了，压缩删掉的内容就真没了。
  • 工具结果 > N 字符时，正文进文件，messages 里只留短摘要 + path（微压缩，零额外 LLM 成本）。

6. 可回查：给 agent 一个 retrieve_archive 工具

这是「可回查」的全部秘密——压缩后 system 里写明 archive 存在，并提供工具。

8. 和官方「Summarize messages」差在哪

LangGraph 文档里的 summarize 模式大致是：summary 字段 + 删旧 messages。
那已经是 compaction；默认缺的是：

能力 官方示例常见形态 本文
原文保留 常被删掉 append-only archive
摘要后找回 无 retrieve_archive
大工具输出 仍占 messages 外置文件 + 短指针
UI 历史 往往等同 state.messages 应读 archive

所以这不是新框架，是 context engineering 约定：工作记忆可丢，档案不可丢，工具桥接两者。

9. 进阶（按需加）

  1. 分层压缩

    • L1：工具结果截断 / 外置（无 LLM）
    • L2：删过旧 tool message，留「调用了 X，结果见 path」
    • L3：LLM 摘要（本文 compact 节点）

  2. Store 替代 jsonl
    跨机器用 InMemoryStore / Postgres store，namespace=(thread_id, "turns")，retrieve 做语义检索。

  3. 摘要可回滚
    archive 里再写一条 {"type":"compaction_event", "summary":..., "removed_ids":[...]}，调试时可重建压缩前视图。

  4. Prompt cache 友好
    系统提示与工具列表尽量稳定；压缩后新 summary 放在 messages 中段变化区，静态前缀可缓存（Anthropic 场景收益大）。

  5. 不要压缩「正在进行的工具链」
    若最后一条是未完成的 AIMessage(tool_calls=...)，推迟 compact，避免破坏 tool_call / ToolMessage 配对。

10. 最小验收清单

  • 压一次后，state.messages token 明显下降，任务仍能续上
  • 问「刚才那次 pytest 的完整 traceback」，agent 会调 retrieve_archive 且能答对
  • 重启进程 + 同一 thread_id + 同一 archive_path，回查仍可用
  • UI 展示的历史来自 archive，不是来自已裁短的 messages
  • 压缩不会拆开未完成的 tool call 对

11. 一句话收束

可回查的 compaction = 有损工作记忆 + 无损档案 + 检索工具。

LangGraph 负责编排与 checkpoint；你要显式建那条「档案 ↔ 工作记忆」的桥。桥建好之后，「只能一股脑把历史丢回模型」就不再是唯一选项——而是最后才对当前窗口里的那一小段工作记忆这么做。

下一步若要落地到仓库，可以再拆一篇：把上述节点收成可 import 的 RetrievableCompactionMiddleware（或 LangGraph 节点包），并接上现有的 agent runtime。
