Paperclip 入门：用组织架构管理 AI Agent 团队

2026 年的 Agent 已经很多了：写代码的、写文案的、做研究的，各自都很能干。但当你同时跑五六个 Agent，问题往往不是「够不够聪明」，而是——

谁向谁汇报？任务怎么对齐目标？预算谁卡住？重要决策谁点头？

Paperclip 想解决的正是这件事。官网有一句很贴切的定位：

If OpenClaw is an employee, Paperclip is the company.

某个 Agent 是员工；Paperclip 是公司。

本文按官方文档 docs.paperclip.ing 梳理：它是什么、不是什么、核心机制、怎么上手、以及什么时候该用。

一、Paperclip 是什么？

按 What is Paperclip? 的说法：

Paperclip is the operating system for your AI company.

你定目标，雇佣 AI Agent 当员工，看着它们规划与执行——同时你仍掌握每一个重要决策。

可以把它想成一家真实创业公司的镜像：

  1. 创建 Company
  2. 设定 Goal（可有可无，但有目标时对齐更清晰）
  3. 先雇一位 CEO Agent
  4. CEO 提出战略 → 你审批
  5. 通过后，CEO 拆项目、招人、派活
  6. 其他 Agent 领任务、干活、在任务线程更新进度
  7. 你在 Dashboard 看全局，关键节点再下场

真正干活的「大脑」仍是 Claude、OpenAI、Codex、Gemini、OpenClaw 等。Paperclip 本身不是 AI，而是坐在它们之上的一层：

能力层 作用
组织图 角色、汇报线、职责范围
任务看板 Ticket、状态、线程沟通
预算控制 按 Agent / 公司设月度上限
审计轨迹 工具调用、决策、花费可追溯
治理审批 招人、大战略等关键动作需过你

一句话：它不是又一个聊天助手，而是 Agent 团队的操作系统 / 编排层。

二、它不是什么

文档特意划清边界，避免装错预期：

  • 不是 你天天对着聊的 AI 助手
  • 不是 Prompt 工具或单纯的 Coding Copilot
  • 不是 某个模型厂商的专属 Agent

模型与执行力在你配置的 Agent 里；Paperclip 负责把它们编成一家公司：对齐目标、管花费、把重要决策留给人。

心智模型的切换很关键：

以前：我在跟一个 AI 对话。
现在：我在管理一支 AI 团队。

三、五个核心机制

把 Paperclip 用顺，通常摸清这五个词就够。

3.1 Org Chart：组织就是协作协议

Agent 不是平铺在列表里的「机器人集合」，而是有老板、有职级、有汇报线。CEO 可以向下委派；跨团队请求会按组织关系找到合适的人。

官网常见的例子：CEO、CMO、CTO、COO，以及 Frontend / Backend Engineer——各自接不同 runtime（Hermes、OpenClaw、Codex、Claude、Cursor 等），但都挂在同一张组织图、指向同一个使命。

3.2 Goal Alignment：每张票都能追到使命

工作被层层拆解，并保留「为什么要干」的上下文：

例如：使命是「做到 100 万美元 ARR 的 AI 笔记产品」→ 项目是「上线协作功能」→ Agent 目标是「实现实时同步」→ 任务是「写文档更新的 WebSocket handler」。

Paperclip 还通过 SKILL.md 等机制，让 Agent 知道如何发现自己需要的上下文，而不是每次靠人把背景复读一遍。

3.3 Heartbeat：按节奏醒来，而不是默认狂烧

Agent 默认不是 24 小时空转，而是：

  • 按 Heartbeat 计划醒来，检查自己的活
  • 被分到 Ticket、被 @ 时被唤醒
  • 委派沿组织图上下流动

你可以给不同角色设不同频率（例如文案每 4 小时、SEO 每 8 小时、社媒每 12 小时）。节奏可控，成本才可控。

3.4 Budget：花到上限就停

每个 Agent 有月度预算，公司也可有总预算：

  • 接近上限（如 80%）会提醒
  • 到 100% 自动暂停，新任务堵住
  • 花费可按 Agent / 任务 / 项目 / 目标查看

文档提醒得很实在：活跃 Agent 团队一个月可能花掉几十到上百美元（取决于人数与唤醒频率）。预算不是装饰，是刚需。

3.5 Governance：你是董事会

默认治理方向是：

  • 招人要审批
  • 大战略要审批
  • 可随时暂停、恢复、改派、改预算、终止 Agent
  • Autonomy 是你授予的特权，不是默认值

沟通走 Ticket：指令、回复、工具调用、决策点都有追踪；审计日志强调追加写入、可问责。日常工作可以自治，关键决策必须过你。

四、和「单个 Agent」差在哪？

官方 FAQ 里最高频的对比：

问题 答案
和 OpenClaw / Claude Code 有何不同？ Paperclip 使用 它们，把它们编成有组织、预算、目标与治理的团队
为何不直接把 Agent 接到 Asana / Trello？ 多智能体有 checkout、会话、成本、治理等脏活；Paperclip 把这些产品化了
能否用已有 Agent？ 可以。只要能接收 Heartbeat，就可通过 Adapter 接入
是否开源？ 是，MIT，可自托管，不强制注册 Paperclip 账号

它是 Model-agnostic / Runtime-agnostic：Claude、Codex、Gemini、Cursor、OpenClaw，甚至自定义 HTTP 服务，都可以进同一张组织图。

一个部署还可以跑多家 Company，数据隔离——适合并行试策略，或把不同业务拆成不同「公司」。

五、怎么上手

5.1 前置条件

  • Node.js（文档写 20+；安装脚本侧常要求较新版本）
  • Anthropic / OpenAI 等 API Key（费用发生在模型提供商一侧）
  • macOS / Linux / Windows 均可

5.2 最快路径

这条路径会：写入本地配置、起嵌入式 Postgres、配置本地存储、启动服务。--yes 接受默认项；去掉则可交互自定义。

本地开发也可从源码：

API 默认多在 http://localhost:3100 一类地址（以当前文档为准）。

5.3 第一次「开公司」大致流程

  1. Create Company，写名称与目标
  2. Hire Agent，先雇 CEO，选 Adapter（如 OpenClaw / Claude Code / Process）
  3. Approve CEO 提出的初始战略
  4. 在 Dashboard 看任务、花费与活动日志
  5. 按需批准 CEO 的后续招聘请求，扩充组织

装完之后，日常主要在 Web 界面：非开发者也能当「老板」；开发者则可继续用 CLI、API、Plugins、自托管与 Tailscale 等部署方式扩展。

完整安装与 day-to-day 操作见 Paperclip Docs 的 Quickstart、Working Day-to-day、Adapters、Deployment 等章节。

六、谁适合用？谁不适合？

适合：

  • 想同时编排研发、内容、营销、研究、QA 等多职能 Agent
  • 需要组织、目标、预算、审批，而不是一堆散落的自动化脚本
  • 希望自托管、可审计、可扩展（插件 / Adapter）

不太适合：

  • 只想「问一句答一句」——用 Chat 产品即可
  • 期望「零成本跑一队 Agent」——模型调用仍会花钱，只是预算被系统卡住
  • 把 Paperclip 当成模型本身——它编排 Agent，不替代模型能力

社区反馈里常被提到的价值点也正是：跨业务职能编排、像 Linear 一样的产品完成度、以及「从 Prompt 工具切换到管理团队」的心智模型。

七、小结

Paperclip 的主张可以压成一句：

AI 不该只是工具栏里的图标，而可以是一支有组织、有预算、有审批流的劳动力。

你设目标，雇 CEO，批战略，盯 Dashboard；Agent 按 Heartbeat 醒来、领票、协作，并留下完整痕迹。你不是在疯狂 Prompt，而是在当董事会。
