Warp 中文文档：Agentic Development Environment 操作指南（十一章）

Warp 中文文档：Agentic Development Environment 操作指南

本文基于 Warp 官方文档 归纳整理为 11 章操作指南，方便上手与日常查阅。原文持续更新，细节与截图以官方为准。

Warp 是开源的 智能体开发环境（Agentic Development Environment）：高性能终端 + 内置/第三方 Agents；智能体能力由 Oz 编排，可本地交互，也可云端自动化。

一、认识 Warp 与 Oz

1.1 Warp 是什么

Warp 把「现代终端」和「编码 Agent」放在同一产品里：

能力 作用
终端 / Agent 双模式 干净跑命令，或进入多轮对话让 Agent 写代码、调试、跑任务
现代终端 UX Block 导航、多行编辑、语法高亮、补全；Rust 实现
内置代码编辑器 文件树、LSP、交互式 Code Review
第三方 CLI Agents 在 Warp 里跑 Claude Code、Codex、OpenCode，并叠加富输入、通知、审查等

1.2 Oz 是什么

Oz 是 Warp 智能能力的编排平台，支持多模型，分两种运行形态：

  • 本地 Agents：在 Warp 应用内实时交互——写/改代码、调试、跑命令、多步规划；你可中途纠偏、审批操作。
  • 云端 Agents：在 Warp（或自建）基础设施后台跑——Slack/Linear/GitHub/Webhook 触发、定时任务、多仓并行、可审计可分享。

二者可交接：云端开的任务可在本地接管；Warp Drive、Rules、MCP 两边共用。

1.3 约 10 分钟快速上手

  1. 安装：从 下载页 安装，或 brew install --cask warp / winget install Warp.Warp。
  2. 跑命令看 Blocks：例如 ls -la。命令与输出组成一个 Block，可单独复制、筛选、跳转。
  3. 试用输入编辑器：Shift+Enter 多行；可鼠标点选编辑，像文本编辑器。
  4. 自动建议 / Tab 补全：历史淡色建议按 → 接受；Tab 补全命令与路径；输错会提示纠正。
  5. 第一次问 Agent：⌘↩（macOS）或 Ctrl+Shift+Enter（Windows/Linux）进入 Agent Mode，例如：

在终端模式里直接打自然语言时，Warp 也会识别并提示发给 Agent。

官方入口：Quickstart · docs.warp.dev

二、安装、迁移与自定义

2.1 安装与环境要求

平台 要点
macOS 10.14+，支持 Metal；Homebrew cask 或拖入 Applications
Windows Win10 1903+ / Server 2022+（需 ConPTY）；WinGet：Warp.Warp
Linux glibc ≥ 2.31，OpenGL ES 3.0+ 或 Vulkan；deb/rpm/pacman/AppImage 等

可选登录账号；首次联网后可离线使用（AI、实时协作等需网络）。默认加载 login shell，支持 bash / zsh / fish / PowerShell；可在 Settings → Features → Session 改启动 shell。

客户端 AGPL v3 开源：warpdotdev/warp。日常建议用官方包；自编译 warp-oss 使用独立配置目录、不自动更新。

详解：Installation and setup

2.2 从其他工具迁过来

官方按来源提供迁移页（设置对照 + 部分自动导入）：

  • iTerm2：内置导入器，可迁主题、字体、热键窗口等
  • Cursor / VS Code / Ghostty / Terminal.app / Windows Terminal：可用 Agent + modify-settings skill 帮你把配置写进 settings.toml
  • Claude Code：可继续在 Warp 终端里跑 claude；也可切到内置 Agent Mode（项目规则对应 AGENTS.md / WARP.md）

总入口：Migrate to Warp

2.3 自定义速查

想改什么 去哪
主题 / 字体 / 图标 / 透明度 Settings → Appearance
Prompt chips（目录、git 分支等） 右键提示符 → Edit prompt
快捷键 Settings → Keyboard shortcuts；可从其他终端导入
垂直标签 / Tab Configs Appearance → Tabs；Features 或 / 菜单
AI 模型 Agent 对话里的模型选择器（Claude / GPT / Gemini / Auto）
Agent 自主度 Settings → Agents → Profiles
新标签默认终端 or Agent Settings → Agents → Warp Agent → Input
直接改配置文件 Settings 底部 Open settings file → settings.toml

详解：Customizing Warp

三、终端核心：Blocks 与输入编辑器

3.1 Blocks 是什么

每个「命令 + 输出」组成一个 Block：

  • 非零退出码的 Block 会用红色侧栏/背景标出
  • 可单选、多选（⌘/Shift 或 Ctrl+Shift）、书签、分享、重新输入（含 sudo）
  • 长输出可用 Sticky Command Header 钉住命令行；块内可滚到顶/底

基础操作见 Block basics。还有过滤、查找、后台 Blocks、Block 分享等扩展能力。

3.2 输入不只是 prompt

Warp 输入区是真正的编辑器：

  • 多行、多光标、折叠、Vim 键位（可开）
  • 别名展开、Command Inspector（退出码、耗时、工作目录）
  • 语法与错误高亮、命令纠正

3.3 补全与命令历史

  • Autosuggestions：基于历史的行内淡色建议
  • Tab completions：增强版补全
  • Command search / history：Ctrl+R 等
  • YAML Workflows：可复用命令工作流
  • 同步输入：多分屏同步打字（适合对照环境）

3.4 Warpify 与 SSH

通过 Warpify，子 shell / SSH 会话也能用上 Blocks、工作目录跟踪等 Warp 特性。详见 Warpify overview。

四、窗口、会话与外观

4.1 标签与分屏

  • Tabs / Vertical Tabs：多会话；可着色、改标题
  • Split panes：左右/上下拆分，可调大小、最大化当前窗格
  • Tab Configs：保存布局 + 启动命令，一键恢复工作区
  • Global hotkey（Quake 模式）：全局热键呼出/隐藏 Warp

4.2 会话

  • 会话导航、恢复：重启后尽量恢复标签与窗格布局（注意：CLI Agent 进程通常不会随恢复自动继续跑，需各自 resume）
  • 旧版 Launch Configurations 仍有文档，新工作流优先 Tab Configs

4.3 外观与设置文件

主题（含 YAML 自定义主题）、Prompt、输入位置（顶/底）、透明度与模糊、Pane 变暗、Blocks/Tabs 行为等均可配。

配置可版本管理：settings.toml 路径因平台而异（macOS ~/.warp/，Linux XDG，Windows %APPDATA% 等）。见 Settings · File locations。

Settings Sync（Beta）可跨机器同步设置。

五、本地 Agents 与编程工作流

5.1 Terminal Mode vs Agent Mode

Terminal Mode Agent Mode
用途 正常 shell 与 Oz / Agent 多轮对话
切换 — ⌘I / Ctrl+I，或 ⌘↩ / Ctrl+Shift+Enter
特点 Blocks、补全 自然语言、工具调用、可挂上下文

对话可排队提示、分叉、云同步；Agent 可能中途提问，可回答/跳过。也支持语音输入。

5.2 给 Agent 的上下文

  • Codebase Context：索引 Git 跟踪代码（代码不上传存到 Warp 服务器）；大仓可用 .warpindexingignore 排除
  • @ 引用：文件、代码、选区
  • Blocks / 图片 / URL 作为上下文
  • Warp Drive：Workflows、Notebooks、Prompts、环境变量（默认可作为 Agent 上下文）
  • Rules：全局规则（Drive）或项目根 AGENTS.md / WARP.md（必须大写文件名）
  • MCP：接外部工具与数据源

首次进仓库时，Warp 常会引导索引并生成 AGENTS.md。Agent Mode 里 /init 也可生成规则文件。

5.3 能力清单（常用）

  • 模型选择 / BYOK / 自定义端点与路由器
  • Profiles & Permissions：允许自动执行什么、命令白黑名单
  • Planning / Task Lists / Web Search
  • Full Terminal Use / Computer Use / Browser Use（视套餐与预览功能）
  • Skills / Slash Commands：可复用任务说明与斜杠命令
  • Active AI：根据报错主动建议修复
  • Interactive Code Review：审 Agent 的 diff、留评论让它改

5.5 在仓库里写代码

进 Git 仓后可触发索引与代码生成流：单文件到批量改、按报错修、按自然语言加功能。实践上：打开项目 → 确认索引 → 用 Rules 固化团队约定 → Agent Mode 描述任务 → Code Review 面板审 diff。

导览：Coding in Warp · Agents overview

AI 可在 Settings → Agents → Warp Agent 全局关闭。Warp SOC 2；与签约 LLM 有 Zero Data Retention 策略。

六、代码编辑与 Code Review

6.1 内置编辑器

  • 文件树（Project Explorer）
  • 编辑器 + LSP
  • 查找替换
  • Vim 键绑定（编辑器侧）
  • 命令行可用 warp . 打开目录

6.2 Code Review 与 Worktrees

  • Code Review 面板：集中看 Agent（或本地）变更、行内评论、让 Agent 跟进
  • Git Worktrees：在 Warp 里管理并行工作树，方便多分支/多 Agent

SSH 场景下部分编辑器能力有支持矩阵，见官方 Feature support over SSH。

七、知识与协作：Warp Drive

Warp Drive 是团队知识库与协作面：

对象 用途
Notebooks 可分享的笔记/文档
Workflows 可复用命令工作流
Prompts 保存的提示词
Environment variables 跨会话环境变量（少把密钥写进 shell rc）
Rules 给 Agent 的持久规则
AI-Integrated Objects 与 Agent 联动的 Drive 对象

还可：Agent Mode 里钉选文件/笔记本、Web 上的 Warp Drive、会话分享、团队管理与 Admin Panel。

入口：Warp Drive overview

八、Warp Agent CLI

不必开 GUI，也能在任意终端用 Warp Agent CLI 跑 Agent 对话、权限配置、与云端编排交接。

典型用途：

  • CI / 远程机器上启动对话
  • 自定义配置、模型与用量
  • 权限 Profiles
  • 云端 handoff / 编排相关命令

从 CLI overview · CLI quickstart · CLI reference 入手。更完整的 Oz CLI/API 见第九、十章相关参考。

九、Oz 平台与云端智能体

9.1 何时用云端 Agents

适合「不用盯着屏幕」的工作：PR 审查、Issue 分流、依赖升级、定时清理、集成驱动流水线。能力关键词：Triggers、Schedules、Parallelism、Observability。

控制台：oz.warp.dev · 文档：Cloud agents · Oz Platform

9.2 Environments、Secrets、Runners

  • Environments：云端执行上下文（仓库、setup 命令、镜像等）
  • Secrets：密钥管理与轮换
  • Runners：Warp 托管或自托管 worker（Direct / Docker / Kubernetes 等）
  • Harnesses：Warp Agent、Claude Code、Codex 等运行载体；可做第三方认证

本地 ↔ 云端、云端 ↔ 云端支持 Handoff；可配置工作区快照等高级能力。

9.3 集成与触发

常见集成：Slack、Linear、GitHub / GitHub Actions、GitLab、Bitbucket、Jira、Azure DevOps 等。Triggers 与 Scheduled Agents 覆盖事件驱动与周期任务。

Skills as Agents、Software factory、多智能体编排等面向规模化自动化场景。

9.4 参考面（CLI / API / SDK）

  • Oz CLI：创建/查询 runs、会话共享、MCP、Skills、Artifacts 等
  • API & SDK：可编程创建与监控；含错误码、鉴权、联合身份令牌等
  • 排障页与 quickstart 文档齐全

入口：API & SDK · Oz CLI reference

9.5 Guides 怎么用

官方 Guides 是面向任务的教程（并行 Agents、无人值守、Rules/Skills、MCP 实战、对比 Claude Code、Code Review 等）。上手顺序建议：

  1. 本地 Quickstart + Coding in Warp
  2. Rules + Codebase Context
  3. 一条云端 Scheduled / GitHub 触发流水线
  4. 需要时再上自托管 Runner

十、企业版与安全

面向团队/公司的能力概览：

  • SSO、角色与权限、团队 Admin、账单
  • 架构与部署选项、Trust Center
  • BYOLLM（如 Bedrock、Vertex）、团队托管的 API Key/端点
  • Analytics API、安全概览与 FAQ

入口：Enterprise · Security · SSO

个人/小团队多数功能在标准 Agents + Drive + Oz Web 已够用；企业特性按合同开通。

十一、账单、隐私与排障

11.1 套餐与信用额度

文档涵盖套餐定价、平台 credit、附加额度、退款 FAQ 等。以官网定价页与账户账单为准：Plans & billing

11.2 隐私与数据

  • SOC 2；签约 LLM 零数据保留（不用于训练）
  • 可关闭 AI；Codebase 索引不把源码存到 Warp 服务器（按官方说明）
  • Secret Redaction、隐私与数据控制、遥测相关说明见 Support 文档

11.3 常见排障

问题 方向
登录失败 Login troubleshooting
安装/显示/Shell 异常 Known issues
更新 应用内更新或包管理器渠道
离线 首次启动后可离线；AI/协作不可用
卸载/登出 官方 Logout & uninstall 页
反馈 发送反馈与日志（含各平台日志路径）

社区：贡献指南、Preview/Alpha、推荐计划、Slack 等见 Support & Community。

小结

把 Warp 想成三层即可：

  1. 终端层：Blocks + 编辑器级输入，先把它当更好用的终端。
  2. 本地 Agent 层：Agent Mode / 第三方 CLI + Rules / MCP / Drive，解决「在仓库里干活」。
  3. Oz 云端层：触发、调度、并行、自托管，解决「不用盯着的自动化」。
