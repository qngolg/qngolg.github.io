从零写一个 Pi Extension：自定义工具、命令与权限门

配套阅读：Pi 官方文档长文翻译 · 操作指南 · 官方 Extensions

目标：在本机从空文件开始，做出一个能拦住危险 bash、提供自定义工具与 /todo 命令的扩展，并理解加载位置、热重载与打包。

你将做成什么

一个名为 safe-kit 的扩展，具备：

  1. 权限门：拦截含 rm -rf、sudo、强制 push 等危险命令，弹确认框
  2. 自定义工具：模型可调用的 note 工具，把便签写入项目 .pi/notes/
  3. 斜杠命令：/todo 在页脚显示简易待办，并支持追加
  4. 生命周期：session_start / session_shutdown 正确启停

Pi 故意不内置权限弹窗——这正是扩展该做的事。

九、常见坑

  1. 工厂里开后台资源 → 某些调用路径根本不会开会话，资源泄漏。用 session_start / session_shutdown。
  2. 在 tool_call 里调 ctx.newSession() → 命令专用 API，事件里可能死锁。会话切换放在 registerCommand 的 handler。
  3. 项目扩展不生效 → .pi/extensions 需项目信任；或用 --approve / /trust。
  4. -p 模式乱弹窗 → 先看 ctx.hasUI；无人值守默认拒绝危险操作更稳妥。
  5. 热重载无效 → 确认扩展在可发现目录，而不是只靠一次性 -e。
  6. 把扩展当沙箱 → 权限门可挡一部分误操作，挡不住 prompt injection 与恶意扩展；不可信仓库请容器化。

十、下一步可以做什么

官方 examples/extensions/ 里有更多范例（路径保护、自定义压缩、git checkpoint、贪吃蛇等）。在此基础上常见演进：

方向 思路
路径保护 在 write/edit 的 tool_call 里拦截 .env、node_modules
Git 检查点 每轮 turn_start stash，/tree 回跳时提示 restore
自定义压缩 session_before_compact 换模型或换摘要格式
共享给团队 打成 Pi Package，pi install + 项目 -l
嵌进应用 不用 TUI，改走 SDK / RPC

Pi 的扩展面就是产品差异面：核心保持小，把「你团队真正在乎的护栏与工具」写进几十行 TypeScript——从今天的 safe-kit 开始即可。
