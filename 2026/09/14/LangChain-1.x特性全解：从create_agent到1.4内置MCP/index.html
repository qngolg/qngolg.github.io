LangChain 1.x 特性全解：从 create_agent 到 1.4 内置 MCP

2025 年 10 月，LangChain 发布了 1.0：第一次承诺到 2.0 之前不做破坏性变更。此后大约一年，框架沿着一条很清楚的线演进——把「造 Agent」做成一等公民，用中间件打开 harness，把模型能力、流式协议、MCP 工具生态逐个补齐。

截至 2026 年 9 月，Python 包最新稳定版是 langchain 1.4.0（2026-09-03），运行时依赖 langgraph >= 1.2.11,< 1.3.0。如果你还停在 0.x 的 LLMChain / AgentExecutor，这篇文章会把 1.x 该怎么用、每个小版本加了什么，一次讲清楚。

文中示例默认：

模型字符串按官方文档写成 openai:gpt-5.5、anthropic:claude-sonnet-4-6 这类 provider:model 形式，换成你环境里能调的模型即可。

一、先把三层分清

LangChain 1.x 不再是「什么都能装一点」的工具箱，而是一套分层 Agent 栈：

层 入口 什么时候用
LangGraph StateGraph Agent 循环本身不够用：要自定义图、Saga 补偿、复杂分支
LangChain create_agent 标准「模型调工具直到结束」循环，用中间件定制
Deep Agents create_deep_agent 要规划、虚拟文件系统、子代理委派，不想自己拼 harness

本文只写 LangChain 1.x。LangGraph 组件见仓库里的 LangGraph 入门；数据分析场景见 Data Agent 入门。

官方公式是：

Harness 的工作只有一件：在正确的时间，把正确的上下文交给模型。

二、版本时间线

版本 时间 一句话
1.0.0 2025-10 create_agent、中间件、结构化输出进主循环、标准内容块、命名空间瘦身
1.1.0 之后 Model profiles、按窗口摘要、推断 ProviderStrategy、ModelRetryMiddleware、审核中间件
1.2.0 之后 工具 extras（厂商专属参数 / 客户端内置工具）、ProviderStrategy(strict=True)
1.3.0 之后 Agent 支持 stream_events(version="v3")
1.3.2 / 1.3.3 补丁 PII 同步打码流式输出；HITL 按参数条件打断
1.4.0 2026-09-03 内置 langchain.mcp.MCPAdapter，替代独立 langchain-mcp-adapters

下面先把 1.0 的底座讲透，再按版本写升级点。每个特性最后都有可复制的案例代码。

三、LangChain 1.0：新的底座

3.1 create_agent：标准 Agent 循环

1.0 用 create_agent 取代 langgraph.prebuilt.create_react_agent（后者已废弃）。它底层就是一张 LangGraph：调模型 → 模型选工具 → 执行工具 → 再调模型，直到模型不再要工具。

和旧 AgentExecutor 的差别：

  • 返回值是编译后的 CompiledStateGraph，自带 invoke / ainvoke / stream / stream_events、checkpoint、interrupt
  • 定制点不再是继承一个巨大的 Agent 类，而是往循环上挂 middleware
  • 结构化输出在主循环里完成，不再额外再打一次 LLM

3.4 Middleware：1.0 真正的分水岭

多数 Agent 框架只让你改 prompt 和工具。create_agent 的差异化是 middleware：在循环的固定钩子上插入逻辑，而不改循环本身。

两类钩子：

风格 钩子 时机 典型用途
Node before_agent 每次 invoke 开始一次 加载记忆、校验输入
Node before_model 每次调模型前 裁历史、动态 prompt、跳到 END
Node after_model 模型返回后、工具执行前 HITL 审批、输出护栏
Node after_agent 整次 invoke 结束 落库、通知、清理
Wrap wrap_model_call 包住整次模型调用 重试、缓存、换模型/换工具
Wrap wrap_tool_call 包住整次工具调用 超时、权限门、改写结果

Node 钩子返回 dict 合并进 State；Wrap 钩子决定 handler 调用 0 次（短路）、1 次或多次（重试）。

执行顺序可以记成：

内置中间件（1.0 就带的三件套）

中间件 作用
HumanInTheLoopMiddleware 敏感工具执行前暂停，等人审批 / 改参 / 拒绝
SummarizationMiddleware 上下文接近上限时压缩旧消息
PIIMiddleware 进模型前打码或拦截邮箱、卡号等

HITL 必须配 checkpointer，因为打断后状态要能恢复。

四种人审决定：

决定 含义
approve 按模型原参数执行
edit 改工具名 / 参数后再执行
reject 不执行，把拒绝原因当反馈还给模型
respond 人直接充当工具结果（适合 ask_user），不要用它来「否决」有副作用的工具

3.6 结构化输出：进主循环，少打一次模型

0.x 常见做法是 Agent 跑完再 with_structured_output 补一枪。1.0 把 schema 放进 response_format，在主循环里生成，省延迟和费用。

两种策略：

ProviderStrategy 厂商原生 structured output OpenAI / Anthropic / xAI 等支持时
ToolStrategy 用「提交结果」工具逼模型填 schema 所有支持 tool calling 的模型

直接传 Pydantic / dataclass / TypedDict 时，框架会按模型能力自动选策略（1.1 起读 model profile）。

3.7 标准内容块：跨厂商读推理、引用、工具调用

四、1.1：让框架「认识」模型能力

1.1 的主题是 model profiles：每套 Chat Model 带一份能力清单（数据主要来自 models.dev），中间件和结构化输出按能力自适应，而不是写死 token 上限。

五、1.2：工具层对齐各家「高级玩法」

1.2 只有一个大头：**工具上的 extras**。各家开始提供「工具搜索、延迟加载、服务端 bash、细粒度流式参数」等能力，这些字段不该污染通用 BaseTool API，于是挂到 extras 再原样传给厂商。

同时 ProviderStrategy 增加 strict=True（需厂商支持，如 OpenAI / xAI），强制输出严格贴合 schema。

5.1 extras：延迟加载与工具搜索

七、1.4：MCP 收进核心包

1.4.0 是 2026 年 9 月 3 日刚发的版本。MCP 不再走独立包 langchain-mcp-adapters，而是：

langchain.mcp 仍是 beta：导入会打一次 LangChainBetaWarning，API 可能变。生产请 pin langchain==1.4.0。

旧代码里的 MultiServerMCPClient 换成 MCPAdapter，迁移细节看官方 migration guide。

7.1 MCPAdapter：一种适配器，多种传输

MCPAdapter 根据 target 推断传输，把 MCP 工具变成普通 LangChain tools，再交给 create_agent。

target 传输
https://... 字符串 Streamable HTTP
Path("server.py") stdio 子进程
进程内 FastMCP 实例 内存，适合测试
{"mcpServers": {...}} 多 server
现成 fastmcp.Client 自己管认证 / 协议

字符串必须是 http(s) URL。FastMCP 会先当文件路径解析，所以 MCPAdapter 拒绝「看起来像脚本路径」的字符串，避免配置里的一段路径被拉起来当子进程。

案例代码：连官方文档 MCP，让 Agent 自己查文档

工具对象持有 client，context 退出后 Agent 仍可用（连接生命周期按 FastMCP 的约定）。文档 MCP 是公开端点，不用 API key。

相对 1.3.18：

  • 可运行的 langchain.mcp 文档示例

八、把特性串成一个可运行的 Agent

下面这个例子把 1.x 里最常用的几块叠在一起：profile 感知的摘要、PII、模型重试、条件 HITL、结构化最终答案、v3 流式。MCP 按需再挂。

这就是 1.x 推荐的组装方式：一个循环 + 一叠中间件 + 可选 MCP 工具，而不是再造一套 Agent 框架。

十、总结

LangChain 1.x 可以看成四次加厚：

  1. 1.0 把产品收成 create_agent + middleware，结构化输出进主循环，内容块跨厂商，旧 API 进 langchain-classic。
  2. 1.1 用 model profiles 让摘要、策略选择跟着模型走，并补上重试和审核。
  3. 1.2 用 extras 对准各家高级工具协议，结构化输出可 strict。
  4. 1.3–1.4 把流式做成 typed projection，把 MCP 收进核心包，HITL 可以按参数、按 MCP annotation 开门。

如果只记三句话：

  • Agent 循环不要自己写，用 create_agent。
  • 业务差异不要叉循环，写成 middleware。
  • 外部工具优先 MCP（1.4）或 @tool；需要厂商黑科技时走 extras。
