一、三个文件，各管一件事

第一次配 model 最容易搞混的地方：omp 把「选哪个模型」和「怎么连这个模型」拆成了两个文件，凭据又放第三个地方。

文件 位置 管什么 谁写它
config.yml ~/.omp/agent/config.yml 策略：角色 → 模型、循环顺序、启用/禁用、思考级别、重试与 fallback /settings、omp config set、选择器里的角色分配
models.yml ~/.omp/agent/models.yml 目录：自定义提供商、模型元数据（上下文、价格、能力）、兼容性 hack 手写（omp config 不管它）
agent.db ~/.omp/agent/agent.db 凭据：OAuth token 与 /login 存下的 API key /login、/logout

要点：

  • 角色只存「选择器字符串」（provider/modelId 或模糊模式），不存密钥；
  • models.yml 的 apiKey: 可以先当环境变量名解析，找不到才当字面 token；
  • config.yml 优先级：CLI 参数 > 环境变量 > config.yml > 内置默认值。

二、角色（roles）：omp 的核心抽象

角色是 omp 在特定时刻使用的具名模型槽位。给每个角色钉一个模型后，Agent 会自己挑，不需要你每轮指定。

十个内置角色

角色 UI 标签 颜色 什么时候用
default DEFAULT / Default success 所有没被更具体角色覆盖的轮次：常规实现、交互对话、工具调用
smol SMOL / Fast warning 轻量活：标题生成、分类、重试摘要；应钉 haiku / mini / nano 一类
slow SLOW / Thinking accent 深度推理：架构决策、棘手调试、错一次的代价高于多花钱的调用
vision VISION / Vision error 图像能力的回退；给不带图能力的模型挂图时用它描述图片
plan PLAN / Architect muted /plan 规划模式的旁路轮次与计划审阅
designer DESIGNER / Designer muted 设计器子代理（UI/UX 实现、无障碍与视觉审查）
commit COMMIT / Commit dim /commit 生成提交信息
tiny TINY / Tiny dim 轻量后台任务：会话标题、记忆、auto 思考难度分类、意外停止检测
task TASK / Subtask muted 子代理工作
advisor ADVISOR / Advisor accent Advisor 旁观评审模型

角色继承链

几个角色在未赋值时不会消失，而是沿链回退：

tiny 明确写成「没设就用 @smol」；advisor 的内部 fallback 目标是 slow（源码里的角色默认表 advisor: "slow"、tiny: "smol"）。所以想让 Advisor 跑起来，只开 advisor.enabled 不够，advisor 或 slow 至少有一个要能解析到可用模型。

自动挑选逻辑

角色没钉模型时，omp 按内置优先级表挑一个：

  • smol 优先找 cerebras/zai-glm、gemini-*-flash-lite、gemini-*-flash、haiku、mini 一类；
  • slow 优先找 openai-codex/gpt-5.x、opus-4.x 一类；
  • designer 优先找 gemini-3.x-pro 一类。

这些是「候选模式列表」，按顺序在你已鉴权的模型里做匹配，全落空就退到可用模型列表第一个。所以换订阅或换 provider 后，即使不写任何 modelRoles，omp 通常也能自己挑出合理的模型。

三、角色别名与选择器语法

角色可以用三种写法引用，位置在 modelRoles 的值、enabledModels、cycleOrder、--models、选择器搜索框里通用：

写法 含义 例
@<role> 别名，展开成该角色当前钉的模型 @slow、@advisor
pi/<role> 旧前缀写法，仍被接受 pi/smol
* 等价 @default *

规则细节：

  • 后缀优先：@slow 解析到 openai/gpt-5.5:high，写成 @slow:low 时结果是 openai/gpt-5.5:low——引用方显式加的后缀覆盖被引用方的。
  • 链式引用有环保护：角色 A 指向 B、B 又指向 A 时，解析在重复出现处截断，不会死循环。
  • 支持的模式：精确 provider/modelId、裸 model id（在可用模型里靠模糊/子串匹配）、glob（openai/*、*sonnet*）、?/[...] 通配——只要包含 * ? [ 就按 glob 处理。

思考级别后缀

模型选择器后可追加 :<level>，取值 off、minimal、low、medium、high、xhigh、max、auto。

关键语义：

  • 模型不支持该级别时不会报错，会降到模型支持的最低不低于该档的级别（例如只支持到 high 的模型收到 xhigh 会变成 high）；
  • 写了一个模型完全不认识的字符串（如 :turbo）会退化成模糊匹配整串、失败后回落到无后缀并给出 warning；
  • :auto 是特殊值：表示「交回 defaultThinkingLevel / 难度分类器」，而不是固定某档。

四、/model 选择器：按键与 chip 全解

Alt+M 或 /model 打开的角色选择器（Model Roles 界面）和 Alt+P 的临时选择器是两个组件，前者能改配置、后者只改本次会话。

布局

左栏是焦点作用域（roles / all models / 某提供商 / 未配置凭据的锁定 provider），Tab 在左右两栏之间切；→ 进右栏，← 回左栏。

左栏（作用域列表）

按键 含义
↑ / ↓ 切换作用域（跳过不可用项）
Enter / Space / → 进入右栏
Tab / Shift+Tab 左右栏切换
F5 强制刷新当前 provider 的模型列表（重新探测端点）
Enter（锁定的 provider 行） 走 OAuth 登录

左栏不接收文本输入：搜索只在右栏的模型列表视图里生效（见下），此时左栏的提供商计数会跟着变小，命中为 0 的作用域变灰。

「锁定」的 provider 指 catalog 里有、但你没有任何凭据的——行首图标是灰的，进去只会看到「Set XXX_API_KEY in your environment」和 OAuth 登录入口。

右栏：Roles 视图

按键 含义
↑ / ↓ 移动角色行（到边界循环）
Enter 进入该行的操作（分配模型 / 编辑 fallback）
f 为这个角色加一条重试 fallback
x / Backspace / Delete 清空该角色（回到自动挑选）
t 打开该角色当前模型的思考级别选择
c 切换该角色是否参与 Ctrl+P 循环（写入 cycleOrder）
[ / ] 调整该角色在 cycleOrder 里的位置
Shift+↑ / Shift+↓ 同上（fallback 行里则是调整 fallback 顺序）
n 新建自定义角色
Esc Roles 视图直接关闭选择器；模型列表视图里有搜索词时，第一次 Esc 只清空搜索

角色视图里 j / k 不是方向键——它们不会被当作搜索输入，也不移动光标，按了没反应。移动一律用方向键。（模型列表视图里的字母则进搜索框。）

焦点在左栏（作用域）时 ↑ / ↓ 切作用域；焦点在右栏（角色行）时 ↑ / ↓ 移动行。两者用 Tab / → / ← 切换。

分配模型时的 chip（底部那一行）

选定模型后，底部出现一排可左右切换的 chip，←/→ 选、Enter 执行：

chip 作用
default / smol / slow / … 各角色 分配该角色到这个模型（已分配的显示为 unassign，再按即清空）
project / global 仅当 modelRoleStorage: project 出现——决定写项目配置还是全局配置
fallbacks:<model-id> 为这个具体模型加 fallback 链（模型维度，换角色也仍生效）
fallbacks:<provider>/* 为整个 provider 的模型加 fallback 链
retry-fallback 把该模型塞进 default 角色的 fallback 链
思考级别 chip（inherit / off / auto / 模型支持的档位） 分配时一并确定思考级别

思考级别 chip 的 inherit 只对非 default 角色有意义（表示「跟随模型默认 / 不覆盖」）；default 角色的 auto 会把 defaultThinkingLevel 一起写成 auto。

右栏：Fallback 链编辑

位置 按键 含义
角色行 f 加 fallback，进入模型选择
fallback 行 Enter 换掉这条 fallback
fallback 行 f 在它后面再加一条
fallback 行 x / Delete 删掉这条
fallback 行 [ / ]、Shift+↑/↓ 调整顺序（顺序即尝试顺序）
+ New fallback… Enter / f 先选「保护谁」（某个模型或 provider/*），再选目标
chainKey 行（provider/model） Enter / f 加 fallback
chainKey 行 x 清空整条链

fallback 全部落到 retry.fallbackChains（详见第六节）。

右栏：All models / 某 provider 视图

按键 含义
↑ / ↓、PgUp / PgDn、Home / End 移动
Enter 选中当前模型 → 进入 chip 分配流程
滚轮 / 左键 移动 / 选中（鼠标在行上再点一次 = 激活）
键入字符 搜索（provider 视图内搜；跨 provider 需回 All models）

模型行右侧会显示三列：上下文窗口、价格（$in/$out per M）、以及可用时的吞吐 xx t/s / 首 token 延迟（终端够宽才显示）。选中行的下方还有一行细节：name · ctx · out · $x/y per M · reasoning · vision，以及所有当前解析到这个模型的角色 chip。

当上下文用量已超过某模型的窗口时，该行会标 context>128k；临时切换器里选中它会先询问是否压缩再切换。

五、三条切换路径：Ctrl+P / Alt+P / Alt+M

三者的差别是改什么：

路径 动作 ID 改什么 会写配置文件吗
Ctrl+P / Shift+Ctrl+P app.model.cycleForward / cycleBackward 只切当前会话的活动模型，按 cycleOrder 在角色间轮换 否
Alt+P（/switch） app.model.selectTemporary 只切当前会话，可任选任意模型 否
Alt+M（/model） app.model.select 改角色 → 模型的映射 是（按 modelRoleStorage）

循环顺序

  • 默认 ["smol", "default", "slow"]；
  • 循环的是角色，每次按下取该角色当前解析到的模型；
  • 想临时换一组候选，用 --models 覆盖：

--models 里每一项是 "id[:effort]"，支持 glob，且只影响本次会话的循环列表，不落盘。

Alt+P 的 @ 快捷角色

在临时选择器里输入以 @ 开头的查询，列表切换成「快速角色」：

  • 每行是一个角色（@smol、@default…），按 cycleOrder 着色；
  • Enter = 应用该角色的模型和思考级别，仅本次会话；
  • 这是「我现在想按 slow 的方式干一轮，但不想改配置」的快捷方式。

六、config.yml 中全部 model 相关设置

以下全部键都能用 omp config set <key> <value> 设置，或在 /settings 面板里改（带 UI 元数据的那些）。

6.1 角色与选择器

键 类型 默认 说明
modelRoles record {} 角色 → 模型选择器。空对象表示全自动挑选
modelRoleStorage enum global global 写当前 profile 的全局配置；project 把角色分配写进 <cwd>/.omp/config.yml，项目没写的角色回落到全局
modelTags record {} 自定义角色的元数据：{name, color, hidden}；键不存在时等于新定义一个角色
modelProviderOrder array [] 同一 model id 在多个 provider 都有时，靠前的 provider 优先；未鉴权的跳过
cycleOrder array ["smol","default","slow"] Ctrl+P 轮换的角色顺序
enabledModels array [] 模型白名单，空 = 全部可用。支持 glob 与按路径分区（见下）
disabledProviders array [] 同时管「模型 provider」与「配置发现源」两套 id，凭据检查之前就生效
includeModelInPrompt boolean true 把活动模型名写进系统提示

modelRoleStorage: project 的实际行为：

  • 选择器里出现 project / global 两个 chip；
  • 选 project 只写 modelRoles.<role> 这一个键到 <cwd>/.omp/config.yml；
  • 项目里没定义的角色继续用全局值；omp config set 仍然只写全局文件。

modelTags 定义一个自定义角色：

之后 @reviewer 就能在 --models、fallbackChains、角色别名里用；cycleOrder 里加上它也会进 Ctrl+P。

6.2 按路径分区的数组（enabledModels / disabledProviders）

两个数组除裸字符串外，还接受 {path, models|providers|values} 形态，让一份全局配置在不同目录下表现不同：

  • 路径键可用 path、paths、pathPrefix、pathPrefixes；值键用 models（配 enabledModels）、providers（配 disabledProviders）或两者都接受 values；
  • 匹配条件是「当前 cwd 等于该路径或在其子目录下」。

数组是整体替换而非追加。项目配置里写了 enabledModels，全局那份就完全失效——这是最容易踩的坑。

disabledProviders 是一个 id 命名空间管两个子系统：

子系统 典型 id
模型 provider anthropic、openai、google、groq、ollama、openrouter
配置发现源 claude、codex、gemini、cursor、opencode

禁用 claude（发现源）和禁用 anthropic（模型后端）是两件事。

6.3 思考与采样

键 类型 默认 说明
defaultThinkingLevel enum high minimal/low/medium/high/xhigh/max/auto；--thinking 可覆盖单次运行
hideThinkingBlock boolean false 仅影响显示，不停用模型的思考
proseOnlyThinking boolean true 思考摘要里省略代码块，用省略号替代
omitThinking boolean false 让上游完全不返回思考摘要（provider 支持时）
externalThinking boolean false 私有草稿：停用受支持模型的 reasoning
thinkingBudgets.* number 见上 各档思考的 token 预算
temperature / topP / topK / minP / presencePenalty / repetitionPenalty number -1 -1 = 用 provider/模型的默认值，omp 不发该参数
textVerbosity enum medium low/medium/high，OpenAI Responses / Codex 传输使用

auto 的解析上限由另一个键控制：

autoThinkingMaxEffort: xhigh 表示分类器最高只到 xhigh，只有显式 ultrathink 才可能到 max；设成 max 允许分类器判为「异常困难」时直接上顶档。

6.4 服务档位（service tier）

键 默认 取值
tier.openai none none、auto、default、flex、scale、priority
tier.anthropic none none、priority
tier.google none none、flex、priority
tier.subagent inherit inherit + 上述 OpenAI 家族全集
tier.advisor none inherit + 上述全集
  • OpenAI 族发 service_tier 字段；priority 是付费加速档；
  • Anthropic 的 priority 就是「fast mode」（speed: "fast"），在 Bedrock/Vertex 与 OpenRouter 上被忽略；
  • tier.subagent: inherit 跟随主 Agent 的实时按家族档位（也就是跟着 /fast 走）；
  • 单次运行可用 --service-tier <value> 覆盖，不落盘。

运行时还有 /fast [on|off|status] 可直接切换。

6.5 重试与 fallback 链

键 默认 说明
retry.enabled true 重试瞬时 provider 错误
retry.maxRetries 10 单请求最大重试次数
retry.baseDelayMs / maxDelayMs 500 / 300000 指数退避起点与上限（5 分钟）
retry.modelFallback true 允许切换到 fallback 模型
retry.usageAwareFallback false 用可靠的 coding-plan 配额报告，在硬限额前优先同 provider 的其他账号，再退到 fallback 模型；普通 API key 不参与
retry.usageReservePct 10 剩余额度低于该百分比即视作「接近上限」。未知/未映射的用量不动主模型
retry.usageReservePolicy confirm confirm 询问、auto 自动、fail-closed 直接失败
retry.fallbackRevertPolicy cooldown-expiry cooldown-expiry 抑制窗口结束回主模型；never 一直停在 fallback 直到手动切
retry.fallbackChains {} 见下

fallbackChains 的 key 有四种，选择时按特异性从高到低：

选择顺序：精确 provider/model-id → provider/* 通配 → 当前角色的链 → default 链。冷却中的目标会被跳过。

子代理有自己的链：agent 定义里列多个模型模式时，第一个可解析的是主模型，其余自动成为它的 fallback——fallbackChains 里没有 agent:<name> 这种 key。

6.6 上下文提升（overflow 先换模型再压缩）

  • 开启后，一轮因 context_length_exceeded 失败时，先尝试换到目标模型重试，不行才走压缩；
  • 目标只有一个来源：模型元数据里的 contextPromotionTarget（不自动挑「同 provider 更大窗口的兄弟」）；
  • 目标必须凭据可解析，否则忽略；
  • 切换是临时的：会话历史里记一条 model_change，不改 modelRoles。

6.7 提示词侧的模型相关开关

键 默认 说明

includeWorkspaceTree false 把工作区目录树渲染进系统提示。注意：文件改动会破坏跨会话的 prompt cache
inlineToolDescriptors auto auto/on/off；on 时把完整工具描述放进系统提示、同时剥离 schema 里的 description，避免重复发送
personality default default/friendly/pragmatic/none，渲染进系统提示的人格块

6.8 provider 协议侧

键 默认 说明

providers.kimiApiFormat auto auto/openai/anthropic，Kimi Code 的 API 形态
providers.openaiWebsockets auto auto/off/on，OpenAI Codex 模型的 websocket 策略

6.9 Prewalk：强模型规划、弱模型执行

  • 从当前活动模型开始，在「计划提示的 todo 列表建立后，第一次 edit/write」时切到便宜模型（默认 smol 角色）；
  • 效果：强模型负责规划、提交 todo、起头实现，然后交棒；
  • 单次运行开关：--prewalk / --no-prewalk / --prewalk-into <model>；
  • 相关：--plan-yolo + --plan-yolo-into <model> 是「强制只读规划 → 首个 resolve 自动批准 → 切模型执行」。

6.10 Advisor 侧的模型键

键 默认 说明
advisor.enabled false modelRoles.advisor 能解析到可用模型时才真正启动
advisor.subagents false 也给 spawn 出来的 task/eval 子代理开 advisor
advisor.syncBacklog off off/1/3/5：advisor 落后这么多轮时，主 Agent 最多等 30 秒补上
advisor.immuneTurns 3 concern/blocker 中断后，后续这么多轮只做不打断的旁注

Advisor 没有专属 CLI 标志分配模型——它的模型只能来自 modelRoles.advisor（或回落到 slow）。

七、models.yml：提供商与模型完整字段

models.yml 是目录层配置，omp config 不管理它，手写即可。旧版 models.json 在同一路径会自动迁移一次。

7.1 顶层结构

顶层只有 providers 一个键，未知的顶层键会让 schema 校验失败。

7.2 Provider 级字段

字段 说明
baseUrl 端点；定义自定义模型时必填
apiKey 定义自定义模型时必填（auth: none 除外）。可写成 "!op read op://dev/openai/api-key" 从命令 stdout 取密钥（10 秒超时，成功输出进程内缓存）
api 传输协议，见下表；可在 provider 级或每个模型上给
auth apiKey（默认）/ none（本地无鉴权）/ oauth
authHeader 为 true 且设了 apiKey 时，给模型注入 Authorization: Bearer
headers 附加 HTTP 头；值同样支持 !command
compat 兼容性覆盖，见第八节
disableStrictTools 只有 Anthropic anthropic-messages 的 strict 工具 schema 白名单（bash/python/edit/find）受影响；不改运行时参数校验
discovery 实时发现模型；除 proxy 外，provider 级必须有 api
modelOverrides 按 model id 打补丁（覆盖元数据）
models 完整声明模型列表
remoteCompaction 远程压缩端点；独立即可构成「仅覆盖型 provider」的合法定义
transport 仅 pi-native

允许的 api：

openai-completions · openai-responses · openai-codex-responses · azure-openai-responses · anthropic-messages · bedrock-converse-stream · google-generative-ai · google-gemini-cli · google-vertex

允许的 discovery.type：

ollama · llama.cpp · lm-studio · openai-models-list · proxy · litellm

7.3 Model 级字段（models: 条目与 modelOverrides: 条目同构）

校验规则：

  • id 必填且非空；
  • 给了 contextWindow / maxTokens 就必须是正数；
  • cost 在 models: 条目里四项都是必填，在 modelOverrides: 里都可选；
  • 定义自定义模型时，provider 必须有 baseUrl，且有 apiKey（或 auth: none），且 provider 或模型级有 api。

7.4 仅覆盖型 provider

没有 models 列表（或为空）的 provider 块只做覆盖，适合「把内置 provider 指向代理」或「只补一个模型的元数据」。这类块必须至少定义一项：

baseUrl、apiKey、auth: none、headers、compat、disableStrictTools、modelOverrides、discovery、remoteCompaction。

7.5 加载与合并顺序

每次 refresh 时：

  1. 载入内置目录（bundled providers/models）；
  2. 载入 models.yml；
  3. 把 provider 覆盖（baseUrl、headers、disableStrictTools）应用到内置模型；
  4. 应用 modelOverrides；
  5. 合并自定义 models：同 provider + id 替换，否则追加；
  6. 载入运行时发现的模型（Ollama / llama.cpp / LM Studio / 各 provider manager），再重新应用一遍 modelOverrides。

provider 级 compat 是基线，模型级 compat 深合并覆盖；openRouterRouting、vercelGatewayRouting、extraBody、whenThinking 这些嵌套块按对象深合并。

7.6 隐式发现

不写任何配置时，omp 也会自动挂上这几个本地 provider：

provider api 默认地址 备注
ollama openai-responses OLLAMA_BASE_URL → OLLAMA_HOST → http://127.0.0.1:11434 上下文窗口取 OLLAMA_CONTEXT_LENGTH → /api/show → 128000；OLLAMA_CONTEXT_LENGTH 不会配置 Ollama 的 num_ctx
llama.cpp openai-responses LLAMA_CPP_BASE_URL → http://127.0.0.1:8080 合成的模型条目用本地默认值
lm-studio openai-completions LM_STUDIO_BASE_URL → http://127.0.0.1:1234/v1 走 GET /models；任何 OpenAI 兼容本地服务都能用这条路

litellm 在 LITELLM_API_KEY 或已存鉴权存在时也自动发现，依次探测 /model_group/info → /v2/model/info → /model/info → /v1/model/info，全不可用才退回 GET /models。

7.7 凭据解析顺序

同一 provider 要 key 时，按此顺序取：

  1. 运行时覆盖（--api-key）
  2. models.yml 的 providers.<name>.apiKey
  3. 已存 OAuth 凭据（含刷新）
  4. /login 存下的 API key
  5. 环境变量映射（ANTHROPIC_API_KEY、OPENAI_API_KEY…）
  6. 其他已存 key（如 broker 迁移来的）
  7. ModelRegistry 回退解析（models.yml 的「环境变量名或字面量」语义）

auth: none 的 provider 无需凭据即为「可用」；getAll() 含全部已加载模型，getAvailable() 才过滤出凭据可解析的那些——模型存在但选不到，通常就是卡在这一步。

9.2 查询与维护

omp config 侧：

omp config set 按目标键的 schema 类型解析值：boolean 接受 true/false/yes/no/on/off/1/0；array 要 JSON 数组（'["anthropic","openai"]'）；record 要 JSON 对象（'{"bash":"prompt"}'）；enum 必须精确匹配。

注意环境变量不是一个统一层——每个变量由拥有它的功能单独读取，且从不回写 config.yml。直接映射到设置的只有 PI_SMOL_MODEL / PI_SLOW_MODEL / PI_PLAN_MODEL（以及 PI_NO_PTY 等少数几项）。

十一、排错清单

现象 原因与修法
选了模型但一轮后变回去 用了 Alt+P（临时）。要持久改角色用 Alt+M 或 modelRoles
角色配了却没生效 选择器字符串解析不到。跑 omp models find <关键词> 确认 id 存在；裸 id 有歧义时写全 provider/modelId
Ctrl+P 循环里没有想要的模型 不在 cycleOrder 对应角色里，或被 enabledModels 过滤掉了
项目里行为和别处不同 项目写了 enabledModels / disabledProviders 等数组 → 整体替换全局
角色分配没写进项目 modelRoleStorage 仍是 global，或 chip 选成了 global
Advisor 开着但不干活 modelRoles.advisor 与 slow 都无法解析到可用模型
自定义 provider 的模型不出现在 /model models.yml 校验失败 → registry 退回内置目录。看 UI 通知或 omp models 输出
模型存在却选不到 凭据解析失败（getAll() 有、getAvailable() 没有）。按 7.7 的顺序补 key
fallback 没触发 retry.modelFallback 为 false，或目标选择器冷却中/不合法（启动时的 config warning 会点出来）
网关代理返回 400 提到 strict provider 级加 disableStrictTools: true
换了订阅后提示「模型不可用」 角色钉的是旧 provider。改成 @smol 一类别名让自动挑选接手，或重跑 omp models refresh

总结

  • 一句话分层：config.yml 决定「用谁」（角色/循环/白名单），models.yml 决定「怎么连」（端点/元数据/兼容），agent.db 存凭据。
  • 十个角色：default、smol、slow、vision、plan、designer、commit、tiny、task、advisor；tiny → smol、advisor → slow 有继承链，角色之间还能用 @role 互相引用。
  • 三种切换：Ctrl+P 按 cycleOrder 循环（只改会话）、Alt+P 临时选（只改会话、支持 @ 快捷角色）、Alt+M 改角色（按 modelRoleStorage 落盘）。
  • 选择器里最重要的几个键：f 加 fallback、t 改思考级别、x 清空角色、c 进出循环、n 新建角色、Tab 切左右栏。
  • 别忘校验：每次改完跑 omp models 与 omp config get modelRoles，比在 TUI 里猜快得多。
